An integration gives your agents tools — a way to search the web, read your support inbox, publish a page, or
generate an image. BoostGPT speaks the **Model Context Protocol (MCP)**, so a connection is a set of tools your
agents can call, described well enough for them to know when to reach for one.

## Three ways to connect

<CardGroup cols={3}>
  <Card title="Managed connectors" icon="plug" href="/integrations/connectors/overview">
    BoostGPT builds and maintains these. Enter one credential; when a vendor changes an endpoint, that is ours
    to fix.
  </Card>
  <Card title="Remote MCP servers" icon="server" href="/integrations/remote-mcp">
    The vendor runs the server. You sign in and approve access — there is no key to paste and no app to register.
  </Card>
  <Card title="Bring your own" icon="code" href="/integrations/custom/overview">
    An OpenAPI specification, a Postman collection, or the address of any MCP server.
  </Card>
</CardGroup>

## Grouped by what they are for

Both catalogues are grouped by the loop BoostGPT works in, rather than alphabetically:

| | |
|---|---|
| **Build** | Make images, video and voice for the site — and know what shipped |
| **Talk** | Reach the audience |
| **Learn** | Research what people search for, and what customers keep asking |
| **Improve** | Work on the site itself |

The featured entries in each group are the ones that change what the Site says or what the Widget answers.
Everything else is one click away under **Show more**.

## Connecting one

<Steps>
  <Step title="Connect it once, for the workspace">
    **Connectors** in the dashboard. A credential you enter is checked against the vendor before anything is
    saved, and a server that signs in is saved only once the sign-in succeeds — so a connection that exists is
    one that works.
  </Step>
  <Step title="Give it to the agents that need it">
    Each agent has its own **Connectors** tab. A connection is shared, so adding it to a second agent asks for
    no credential; switching a tool off for one agent does not touch another.
  </Step>
  <Step title="Decide what needs asking first">
    Every connection carries an approval setting — every time, never, or per tool. An agent can always ask more
    often than you set, never less.
  </Step>
</Steps>

<Note>
  Two connectors need no setup at all: **Serper** for web search and **Pexels** for photography are funded by
  BoostGPT and attached to a new agent automatically. Your own key always takes precedence over ours.
</Note>

## What an agent does with them

Tools are not a menu the agent reads top to bottom. It picks by the description, which is why every entry in
these catalogues says what it is *for* rather than what its API does — and why a tool you switch off disappears
from the agent's view entirely rather than being refused at call time.
